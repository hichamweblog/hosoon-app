## Supabase محلي / staging فقط أولًا

1. استخدم مشروعًا اختباريًا جديدًا، لا مشروع الإنتاج. انسخ `.env.local.example` إلى `.env.local` **محليًا فقط** وضع إعدادات مشروعك عبر إدارة البيئة، لا في Git أو المحادثة.
2. عند توفر Docker، `npx --yes supabase@2.75.0 start` ثم `npx --yes supabase@2.75.0 db reset --local` ينشئان بيئة **محلية قابلة للمسح**. لا تستعمل `db reset` على إنتاج، ولا `db push` قبل المراجعة.
3. الترحيل `202610020000_legacy_baseline.sql` لإنشاء الأساس عند غيابه، و`202610020001_safe_progress.sql` لإضافة snapshot/revision/epoch والقيود ونسخ الرجوع وسياسات RLS وRPC. للمشروع القديم: راجع الملفات وشغّل الترحيلات، لا حذف الجداول وإعادة إنشائها. `schema.sql` تجميع مناسب **لتثبيت جديد**.
4. الترحيل يترك الصفوف القديمة والأعمدة القديمة؛ تحويلها إلى v4 يتم بعد قراءة محققة من عميل جديد. الأرقام القديمة غير الصالحة لا تُصحح/تمحى بصمت. قيود `NOT VALID` تحفظ الصفوف للمراجعة، وتفرض القيود على الكتابات الجديدة. افحص الصفوف القديمة قبل `VALIDATE CONSTRAINT`.
5. الكتابة المباشرة القديمة إلى `user_progress` تُمنع عمدًا. الكتابة الجديدة فقط عبر `save_hosoon_progress` مع CAS؛ إعادة الضبط/الاستيراد عبر `reset_hosoon_progress` مع epoch جديد ونسخة رجوع سحابية. لهذا لا تُعد العميل القديم كخطة تراجع بعد الترحيل.
6. `npx --yes supabase@2.75.0 test db` يشغّل pgTAP على المشروع المحلي. يجب إعادة الاختبار بحسابين اختباريين عبر API وJWT الحقيقيين في staging، لا الاكتفاء بسلوك UI.

### منع localhost في متصفح المعاينة

إذا كان Supabase داخل sandbox، اجعل `NEXT_PUBLIC_SUPABASE_URL=/supabase` و`SUPABASE_INTERNAL_URL=http://127.0.0.1:54321`. متصفح المستخدم يتصل **بأصل التطبيق نفسه**؛ Next يمرر الطلب إلى الخادم الداخلي. عيّن `APP_ORIGIN` إلى أصل التطبيق/المعاينة الصحيح. لا تنسخ عنوان localhost إلى كود المتصفح للوصول إلى خدمة أخرى.

### إعداد Auth

- `site_url`: أصل التطبيق الفعلي، وredirects مسموحة صراحة إلى الأصل و`/auth/recovery`.
- لا wildcard مفتوحًا لروابط الاستعادة/الدخول. أضف أصل المعاينة الدقيق في staging عند الحاجة.
- فعّل سياسة كلمة المرور وتأكيد البريد المناسبة. صفحة recovery تتعامل مع جلسة صالحة/رابط منتهي؛ روابط recovery القديمة إلى `/` تُحوَّل إلى المسار الجديد.
- `SUPABASE_SERVICE_ROLE_KEY` متغير **جهة الخادم فقط** لحذف الحساب؛ لا يبدأ بـ`NEXT_PUBLIC_`. API يتحقق من JWT ونية المالك قبل الحذف. إذا لم يُضبط، الاستجابة 503 ولا ادعاء حذف.
- حذف Auth يحذف تقدم الحساب ونسخ الرجوع والتفسيرات الخاصة بالاقتراحات عبر cascade. ملفات التصدير أو نسخ الأجهزة غير المتصلة لا يمكن محوها عن بعد.

## بوابة إطلاق ملزمة

- [ ] نسخ قاعدة البيانات والتصدير من جهاز قديم قبل الترحيل.
- [ ] RLS: A لا يقرأ/يكتب/يحذف بيانات B، والضيف لا ينقل دون موافقة، ولا يمكن اعتماد اقتراح ذاتيًا.
- [ ] CAS: تعديلان متزامنان + تراجع وحذف ملاحظة + reconnect بعد reset لا تعيد القديم.
- [ ] SDK الحقيقي: دخول/خروج/انتهاء الجلسة، رابط سحري، recovery فعلي وكلمة مرور جديدة، وحذف الحساب مع نجاح/فشل admin.
- [ ] اختبار iOS Safari/Android الفعلي: تثبيت، quota، offline cold opening، إذن إشعارات محلي، وعودة من القارئ.
- [ ] مراجعة مختص لمواءمة منهج المراجعة مع المحفوظ غير المتصل، والمصدر/الحدود/الصفحات المشتركة. اختبارات البيانات ليست شهادة دينية.
- [ ] تغيير `APP_RELEASE_VERSION` في **كل نشر**؛ عامل الخدمة لا يفعّل تحديثًا قسريًا وسط جلسة.

## النسخ والتراجع

- نقل/تخزين v4، ودعم بيانات v0–v3 المعروفة. الرصيد القديم adjustment مستقل؛ لا يمكن استنتاج تواريخ دقيقة من علامات رحلة قديمة.
- قبل استبدال/إعادة ضبط، نسخة محلية (حتى 3 لكل مالك). reset الحساب يحفظ نسخة الخادم أيضًا في `progress_recoveries` (3 أحدث)، قابلة للتصدير من الإعدادات.
- النسخة المشوهة أو المستقبلية لا تستبدل الحالة بالافتراضيات. يظهر وضع قراءة/تصدير؛ الأصل قابل للتصدير دون تعديل.
- التراجع الآمن: عميل يفهم v4 أو إصلاح forward. لاستعادة snapshot قديمة، استوردها عبر RPC **بحقبة جديدة**. لا تخفض epoch/revision ولا تستعد عميل OR/max قديمًا إلى الكتابة.
- مسح نسخة الحساب من جهاز ليس تصفير السحابة. بيانات الضيف مستقلة. تصدير JSON يحتوي ملاحظات شخصية، وليس ملفًا مشفرًا.

## offline والصوت والتذكير

الهيكل/fonts/chunks والفهرس فقط precache؛ **لا 485 صورة تلقائيًا**. الصور تُنزّل بنطاق واضح وحجم وتقدم وإلغاء، وتتحقق SHA-256 قبل cache. المتصفح قد يزيل مخزونه؛ التقدم مستقل عن الصور. الصوت الخارجي غير مُدار كتنزيل offline؛ الاختبارات الصوتية تستعمل WAV fixtures، ولا تثبت توفر/سلامة التسجيلات الخارجية على كل هاتف.

التذكير بإذن صريح، أثناء فتح التطبيق بأفضل جهد، مع cleanup وAPI عامل الخدمة للهاتف. لا Push في الخلفية، ولا ضمان بعد قتل التطبيق. الجلسة تستمر عند فتح القارئ، لكن استئناف مؤقت حي بعد قتل المتصفح ليس وعد هذا الإصدار؛ التقدم/الملاحظات المحفوظة لا تُمسح.
